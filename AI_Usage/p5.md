# AI Usage: Evaluation and Non-Functional Testing

My part was the evaluation and measurement part of the project. I used AI assistance to plan how the project should be tested both functionally and non-functionally.

The main idea I gave was that the project should not only check whether connectivity fails, but should also measure non-functional requirements. The specific non-functional requirements were:

- performance;
- simplicity;
- robustness.

For measurement, I mentioned the following metrics:

- delay and latency;
- bandwidth and throughput;
- loss;
- burst loss;
- jitter.

These points were used to shape the evaluation scripts and the report section. The evaluation measured detection time, classifier accuracy, RTT, jitter, loss rate, burst loss, throughput, bytes sent, and probe count.

## Later Bug Fix

Later, while running the evaluation, a bug appeared in the cleanup flow of the fault-injection script. The script assumed that a running agent pod would always be present and failed when Kubernetes returned an empty pod list. I fixed this bug myself by making the cleanup path safe when a pod is missing or the fault has already been cleared.

This made the evaluation script more robust because repeated runs could continue even when cleanup had nothing left to remove.
