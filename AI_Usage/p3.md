# AI Usage: Operator and Kubernetes API

Siddhesh used AI assistance for P3, which was the operator and Kubernetes API part of the project.

AI was also used to initially generate parts of the project report. The generated report text was manually verified against the code, manually rewritten for clarity and consistency, and the PPT was prepared manually.

His prompt was:

```text
Explain project till now and the work of P3 which I have to complete. Only explore no edits.
```

The AI assistance was used only for exploration and understanding. The discussion explained that the project was a Kubernetes self-healing network operator whose goal was to maintain a live east-west connectivity matrix between pods and nodes, classify failures, and expose results through a Kubernetes custom resource and metrics.

The AI output identified P3 as the part responsible for turning the project from a scaffold into the actual operator layer. It explained that P3 should not only update CRD status, but should act as the control loop that discovers agents, runs probe rounds, builds the matrix, classifies failures, writes status, and optionally triggers safe remediation logic.

The main P3 topics discussed were:

- the `NetworkHealthCheck` custom resource;
- the CRD spec and status schema;
- the controller-runtime reconcile loop;
- discovery of running agent pods by label and node;
- bounded fan-out probing across agent pods;
- filling status with the reachability matrix and verdict;
- respecting the configured probe interval and requeue timing;
- integrating the operator with the analysis/classification layer;
- adding conditions, events, and guarded remediation behavior.

The AI also explained two important concepts in plain language:

- An east-west connectivity matrix means a table showing which pods or nodes inside the cluster can reach each other.
- A CRD, or Custom Resource Definition, lets Kubernetes support a custom object such as `NetworkHealthCheck`, similar to built-in objects like `Pod`, `Service`, or `Deployment`.

This usage helped Siddhesh understand the scope of P3 and the files/directories connected to it:

```text
api/
cmd/manager/
internal/controller/
config/crd/networkhealthcheck-crd.yaml
config/samples/networkhealthcheck-sample.yaml
```
